# User Flow

## Goal

This flow describes how a user creates and reviews a schedule in Orchedule.

The main objective is to keep the process simple enough for beginners while still allowing advanced control.

## Primary Flow

### 1. Start a competition
The user creates a new competition and enters basic information such as name, date range, and status.

### 2. Add teams
The user registers all participating teams.

### 3. Add fields
The user defines the available fields or venues.

### 4. Add time slots
The user configures the available time windows for scheduling.

### 5. Define preferences
The user sets team preferences, such as preferred or undesired slots.

### 6. Configure rules
The user selects the scheduling rules and constraints that must be respected.

### 7. Generate schedule
The system creates a schedule based on preferences, constraints, and fairness rules.

### 8. Review result
The user sees the generated schedule in a calendar or list view.

### 9. Check audit
The user reviews validation results, warnings, and fairness notes.

### 10. Edit if needed
The user can manually adjust assignments and regenerate validation.

### 11. Publish or save
The user saves the final schedule version for later use or export.

## Secondary Flow

### Quick review flow
- Open a schedule.
- Review audit results.
- Inspect fairness distribution.
- Apply small manual edits.
- Confirm the final version.

### Advanced flow
- Create competition.
- Configure custom rules.
- Add detailed preference weights.
- Generate multiple candidate schedules.
- Compare versions.
- Select the best one.

## UX Principles

- Keep the first screen simple.
- Avoid exposing too many technical settings too early.
- Make the result understandable at a glance.
- Use visual feedback for fairness and conflicts.
- Support both fast use and deep control.

## Key Screens

- Competition list.
- Competition editor.
- Teams manager.
- Fields manager.
- Time slots manager.
- Preferences screen.
- Schedule generation screen.
- Calendar view.
- Audit view.
- Schedule version comparison.
